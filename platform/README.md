# QAZAQMETAL KÁSIPODAǴY · рабочая платформа

Этот каталог содержит новую серверную систему и общий Flutter-клиент для Android, iOS и браузера. Старые `mobile/`, `index.html`, `app.js` и материалы презентаций сохранены отдельно.

## Состав

- `server/`: FastAPI, PostgreSQL, миграции Alembic, роли, сессии, пароли Argon2id, каталог, QR, история, модерация, статистика, загрузка изображений и CSV.
- `client/`: нативный Flutter UI; тот же клиент компилируется в веб-версию. Внутри нет WebView.
- `web/`: подготовленная веб-сборка для сервера; создаётся командой ниже.
- `compose.yaml`, `deploy/`: PostgreSQL, API, HTTPS через Caddy, постоянные тома.
- `scripts/`: сборка, резервное копирование и восстановление.
- `docs/`: инструкции администратора, партнёра, участника, ограничения сборки и публикации.

## Доступ и первый вход

Свободной регистрации нет. Администратор создаёт организацию, добавляет работников вручную или CSV, выдаёт каждому отдельный временный пароль. Основной идентификатор — табельный номер, телефон необязателен. При совпадении табельных номеров в разных организациях используется код организации. При первом входе сервер разрешает только установку собственного пароля, просмотр собственного аккаунта и выход.

Сессия действует 30 дней: Android/iOS сохраняют непрозрачный токен в защищённом хранилище платформы; браузер использует `HttpOnly`, `SameSite=Strict` cookie, `Secure` при production. В БД хранится только SHA-256 токена. Пароли хешируются Argon2id. Смена пароля отзывает все прежние сессии и создаёт новую. Выход отзывает все сессии аккаунта; блокировка, увольнение, отключение организации или партнёра закрывают доступ на сервере.

## Запуск для разработки

```sh
cd platform/server
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.lock
alembic upgrade head
python -m app.cli bootstrap-admin --username your-admin
uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Без `DATABASE_URL` используется SQLite только для локальной разработки. Production требует PostgreSQL и HTTPS `PUBLIC_ORIGIN`. Никогда не используйте dev-базу и тестовые пароли для участников. Секреты вводятся на целевом сервере; в репозитории их нет.

## Клиент

Flutter 3.47.9 / Dart 3.13.7; зависимости закреплены `pubspec.lock`.

```sh
cd platform/client
flutter pub get --enforce-lockfile
flutter analyze
flutter test
flutter build web --release --no-web-resources-cdn --no-wasm-dry-run
```

Скопируйте содержимое `client/build/web/` в `platform/web/`. Веб-клиент использует API того же origin. Камера и геолокация в браузере требуют HTTPS (localhost разрешён браузерами для разработки). Веб-декодер ZXing поставляется локально, не подгружается из CDN.

Android debug для USB-проверки локального сервера:

```sh
flutter build apk --debug --dart-define=API_BASE_URL=http://127.0.0.1:8000
adb reverse tcp:8000 tcp:8000
adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

HTTP разрешён только debug-сборке; production использует HTTPS. Для эмулятора вместо USB reverse можно собрать с `http://10.0.2.2:8000`. APK из этой разработки подключается к `127.0.0.1:8000` через USB reverse; это не автономная демо-версия.

Release Android требует своего ключа и реального домена. Настройте `client/android/key.properties` по примеру и выполните:

```sh
flutter build appbundle --release --dart-define=API_BASE_URL=https://your-domain.kz
```

Подпись debug-ключом для release запрещена настройкой Gradle. iOS: смотрите [PUBLISHING.md](docs/PUBLISHING.md). Сборка iOS требует macOS/Xcode.

## Production

1. На сервере Linux установите Docker/Compose, направьте DNS домена на сервер, откройте 80/443.
2. Подготовьте веб-сборку. Скопируйте `.env.example` в `.env`, укажите домен, почту для TLS и два разных случайных URL-safe пароля `DB_PASSWORD` и `ROOT_DB_PASSWORD`.
3. После переноса ZIP выполните `chmod 755 deploy/init-db.sh`, затем `docker compose up -d --build`. PostgreSQL и API не выставляют порты наружу. API использует отдельную роль БД без SUPERUSER/CREATEDB/CREATEROLE. Caddy выдаёт TLS-сертификат.
4. Проверьте `https://DOMAIN/api/health`.
5. Выполните `docker compose exec api python -m app.cli bootstrap-admin --username YOUR_LOGIN` и введите временный пароль интерактивно.
6. Войдите через браузер, задайте личный пароль, создайте организации и партнёров, выдайте доступы. Импортируйте работников и передавайте временные пароли индивидуально.
7. При необходимости импортируйте исходные рекламные данные: `docker compose exec api python -m app.cli import-reference --file reference-partners.json`. Они попадут только в очередь модерации.
8. Проверьте реальные фотографии, адреса, геокоординаты, ограничения, сроки, организации и согласие партнёров до одобрения. Затем выдайте QR для опубликованных заведений.
9. Настройте ежедневный backup и проверьте восстановление на отдельном стенде.

Обновление: резервная копия → новая сборка веба → `docker compose up -d --build` → проверка health и сценариев. Миграции выполняются перед запуском API. Не запускайте два одновременных обновления.

## Проверки

```sh
cd platform/server
pip install -r requirements-dev.txt
python -m pytest -q
ruff check app
alembic check
```

Для прогона на отдельной PostgreSQL установите `TEST_DATABASE_URL` с именем базы `qazaqmetal_test`. **Тесты удаляют и пересоздают таблицы именно в этой тестовой БД.** Никогда не задавайте URL production.

Данные для подключения к будущему серверу, подписи магазинов и сведения реальных работников не нужны для разработки кода, но нужны для публикации. Реальных аккаунтов участников или партнёров в исходниках нет. Сведения из рекламы импортируются как непроверенные черновики, без выдуманных скидок и координат. Оценка сервера на 10 000 зарегистрированных участников остаётся плановой: это не проверка 10 000 одновременных сессий.

Фактические результаты и границы проверок: [docs/VALIDATION.md](docs/VALIDATION.md). Для воспроизводимой браузерной проверки — `scripts/browser_smoke.py`, только на отдельном QA-стенде.
