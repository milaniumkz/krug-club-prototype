# QAZAQMETAL 2.3.1 — push notifications

One Firebase project (`qazaqmetal-8a77b`), independent member/partner registrations for Android, iOS and Web. Public metadata lives in `client/firebase.client.json`; native boot resources are generated by `scripts/configure_firebase_native.py` and automatically regenerated for the partner build. Private service-account JSON is **never** part of source, APKs, web assets or public artifacts.

## Production

- Secret: `/opt/qazaqmetal/shared/firebase_admin.json`, uid10001, mode0400.
- Client configuration and public VAPID key: protected server `.env`, `FIREBASE_CLIENT_CONFIG` / `FIREBASE_WEB_VAPID_KEY`.
- `compose.push.yaml` profile `push` starts the FCM HTTPv1 transactional outbox worker. The overlay and profile are retained in the production `.env` for subsequent deployments.
- Public `/api/push-config` selects role from the portal host and platform from `android|ios|web`. Admin is disabled. `/api/push-config.js` exposes only whitelisted web-client metadata for the service worker.
- Lazy SDK loader: `firebase-loader.js` loads modular SDK12.12.0 without inline script injection; CSP remains strict.
- Firebase service worker: `/firebase-messaging-sw.js`, same-origin pinned Firebase compat12.12.0 libraries. Background messages use FCM standard display, one notification per delivery; clicks use a server-generated same-origin HTTPS link. Foreground messages show an in-app notification.
- The Firebase SDK is pinned to Firebase Messaging16.7.0/core4.14.0 (native Apple SDK12.18.0), using classic FCM registration tokens compatible with the HTTPv1 sender.

## Audiences

- First approved venue: all active eligible **union members** in the venue's allowed organizations.
- New/changed banner or increased discount after moderation: only active union members who saved the venue.
- Reduced/unchanged discount: no increase notice.
- Moderation decision: owner partner's active accounts.
- Before delivery the worker rechecks employment, organization, partner/venue visibility, expiry, ownership of device and favorite subscription. Logout deactivates devices along with revoking sessions. An account switch reassigns that browser/device token; old-account deliveries are cancelled.
- Outbox retries transient failures with backoff, deactivates unregistered tokens, avoids logging tokens, private keys, OAuth responses or FCM error bodies.

## End user

Sign in and open **Notifications → Enable notifications**, then allow in the browser/OS dialog. On Android the app requests the OS permission if not granted. Denied permissions must be changed in device/browser site settings. A user tap can retry registration. Browser notifications require HTTPS, a supported browser and enabled OS notifications. On iOS Web Push requires an installed Home Screen web app and a supported iOS version.
