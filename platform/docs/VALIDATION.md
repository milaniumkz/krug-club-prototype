# Фактические проверки · 14 ноября 2026

## Выполнено

- Python API: **17 тестов на настоящей PostgreSQL**. Миграция Alembic применяется; `alembic check` не видит расхождений схемы.
- Flutter: **9 unit/widget-тестов**, `flutter analyze` без замечаний. Ширины 320, 390, 768, 1440; переход каталог → карточка, пятираздельное меню, обязательная смена пароля, защищённое сохранение токена, повторный запуск API-клиента, кабинет партнёра на узком экране, клавиатура.
- Браузер Chromium с реальным API и отдельной синтетической QA-базой: первый вход → свой пароль → повторное открытие с сохранённой сессией; карта около разрешённой геопозиции, маркеры и атрибуция; создание заведения партнёром → скрытый черновик → одобрение администратором → публикация.
- Сканирование браузерным QR-декодером: камера получает **искусственный видеопоток** с актуальным QA-кодом; API автоматически определяет заведение, возвращает скидку, история содержит операцию. Это именно тест видеопроцесса, но **не физической камеры телефона**.
- QR/API: неверные и отозванные коды, недоступные/истёкшие акции и членство, ограничения организаций, идемпотентность и повторные запросы. Четыре одновременных PostgreSQL-запроса дают одну запись применения.
- Права: участник не управляет контентом; партнёр не получает чужие заведения/статистику; публикация и удаление требуют модерацию. Опубликованная версия сохраняется до одобрения новой.
- Данные: атомарный CSV-импорт с индивидуальными временными паролями; сессии отзываются при смене пароля, выходе, блокировке и увольнении; ошибки валидации не возвращают значения паролей; изображения проверяются и пересохраняются в WebP.
- Docker: production-образ собран и запущен с PostgreSQL; миграции, health, веб-файлы и защитные заголовки работают. Compose проверен с отдельной ролью приложения без SUPERUSER/CREATEDB/CREATEROLE.
- Резервная копия и восстановление проверены на **отдельном пустом QA-стенде**: схема и пустой каталог загрузок. Восстановление реальных объёмов и рабочей базы нужно проверить на целевом сервере.
- Android debug APK собран. iOS release без подписи скомпилирован на macOS/Xcode через GitHub Actions. Общий код также собирается в браузерную release-версию.

## Не выдаётся за проверенное

- Нет подключённого физического Android/iPhone; реальная камера, аппаратная геолокация, разрешения и хранение сессии на телефонах требуют устройства.
- iOS-артефакт проверки не подписан и собран с техническим адресом `https://build-only.invalid`. Он не устанавливается пользователю и не является готовым IPA для App Store. Рабочая iOS-сборка создаётся из исходников после получения домена и подписей.
- Android debug использует `http://127.0.0.1:8000`: для телефона нужен USB `adb reverse`; для релиза — сборка с реальным HTTPS API_BASE_URL и upload keystore.
- Публичный сервер, TLS/DNS настоящего домена, магазины приложений и реальные аккаунты работников ещё не настроены — их доступы и данные заказчик предоставит позже.
- Нет подтверждённого нагрузочного теста на 10 000 одновременных пользователей. 10 000 зарегистрированных участников — плановый ориентир, зависящий от конфигурации и нагрузки.
- Тестовая БД содержит только синтетические QA-аккаунты. Рекламные данные заказчика находятся в отдельном импорте черновиков; актуальность условий, фотографии, геокоординаты и ограничения необходимо подтвердить до публикации.

## Повторение

Сервер: `pip install -r requirements-dev.txt && python -m pytest -q`. PostgreSQL: отдельная `TEST_DATABASE_URL` с именем `qazaqmetal_test`; тесты удаляют её таблицы.

Клиент: `flutter pub get --enforce-lockfile && flutter analyze && flutter test`. Native и web команды описаны в README.

Браузер: установите `server/requirements-browser.txt` и Chromium/ffmpeg; заведите отдельную preview-БД и выполните миграции, затем `python server/tests/seed_browser.py /private/qa-credentials.json`. Запустите API и собранный веб-клиент, выполните `python scripts/browser_smoke.py --credentials /private/qa-credentials.json`. Скрипт отказывается использовать идентификаторы не-QA. Не запускать на рабочей базе.
