# Фактические проверки · фиолетовая версия 2.1.0 · 18 ноября 2026

## Выполнено

- **26 API-тестов на PostgreSQL**: авторизация, обязательная смена пароля, сессии, роли/изоляция партнёров, модерация, QR/повторы/блокировки, импорт, медиа, избранное, история, обращения и статистика. Есть проверки границ отчётных дней по времени Казахстана, отзыва доступа и количества SQL-запросов. Миграции Alembic и `alembic check` прошли; Ruff без замечаний.
- **18 Flutter unit/widget-тестов**, `flutter analyze` без замечаний: сохранение сессии, смена пароля, пять разделов, переход в карточку, обязательный пароль, кабинет на смартфоне, клавиатура, длинные имена на 320 px, истёкшее членство, отзыв доступа, постраничная история, экран экспорта QR и время Казахстана.
- **70 отдельных браузерных сценариев**: 34 навигация/размеры, 14 взаимодействия, 22 вход/администрирование. Это разные сценарии, а не заявление о 50 полных ручных обходах приложения. Chromium выполняет реальные действия с настоящим API на синтетической QA-базе.
- **7 дополнительных сценариев контента**: заполнение полей заведения и загрузка фото, сохранение скидки, загрузка баннера, три этапа публикации через модерацию и скачивание PNG с QR. Модерация в этом дополнительном наборе выполняется API; кнопки модерации проверяются отдельным браузерным smoke-сценарием.
- Выгруженный PNG прочитан ZXing и принят сервером как действующий QR; правильная скидка и запись истории проверены. Коды и тестовые пароли не входят в публичные протоколы.
- Отдельный сквозной smoke: первый пароль → личный пароль → восстановление сессии → карта → заведение партнёра → одобрение администратором → QR из искусственного видеопотока → история. **Это не физическая камера телефона.**
- Размеры браузера: 320×640, 390×844, 430×932, 768×1024, кабинеты 1320×1000; Flutter дополнительно проверяет 1440 px. Проверены клавиатура на малом экране и возврат из вложенных экранов; системные жесты телефонов требуют устройств.
- Чистый Docker Compose: API, PostgreSQL, Caddy, миграции, скомпилированная веб-версия и 30 HTTPS-проверок с доверенным локальным сертификатом. Роль приложения не имеет SUPERUSER/CREATEDB/CREATEROLE. Для сборки в этой облачной среде её CA передан через временный BuildKit secret; проверка TLS не отключалась, CA не включён в проект.
- Резервное копирование/восстановление на заполненной синтетической QA-базе: восстановлены операции истории, проверен хеш изображения и health API. Рабочую базу заказчика не затрагивали.
- Android debug APK и веб release собраны. iOS release без подписи собирается на macOS/Xcode через CI; статус относится к конкретному коммиту. Номер версии — 2.1.0+11. Итоговый отчёт выпуска содержит ссылку на соответствующий CI-run.

## Что осталось вне проверки

- Физические Android/iPhone не подключены: аппаратная камера, GPS, системная панель передачи PNG, фон, жесты и установка на устройства требуют проверки на телефонах.
- iOS validation-артефакт не подписан, собран с техническим `https://build-only.invalid`, не устанавливается пользователю и не является IPA для App Store. Для рабочего релиза нужны реальный адрес API и подписи Apple.
- Android debug использует `http://127.0.0.1:8000`: для проверки через компьютер нужен `adb reverse`. Рабочий APK/AAB собирается с HTTPS-доменом после развёртывания и upload keystore для release.
- Публичный сервер/домен, реальные списки работников, подтверждённые условия и фотографии партнёров, подписи магазинов предоставляются позднее. На сервере заказчика пока ничего не опубликовано.
- Результаты нагрузки 14 ноября — исторические: [PERFORMANCE_REPORT.md](PERFORMANCE_REPORT.md). Поддержка 5 000 RPS и мгновенная обработка 5 000 запросов не подтверждались. 10 000 зарегистрированных участников не равны 10 000 одновременно активных. Производительность нового сервера проверяется после его получения.

## Повторение

Сервер: `cd platform/server && python -m pytest -q && ruff check app && alembic check`. Для конкуренции задайте отдельную `TEST_DATABASE_URL`, содержащую `qazaqmetal_test`: тесты очищают именно тестовую БД.

Клиент: `cd platform/client && flutter analyze && flutter test`.

Браузерные сценарии: `scripts/browser_smoke.py`, `browser_navigation.py`, `browser_interactions.py`, `browser_management.py`, `browser_partner_content.py` — только с синтетическими QA-аккаунтами и отдельной preview-базой. Пароли хранятся в приватном файле, PNG с действующим тестовым QR — в приватной директории. Перед повторением сценариев управления используйте свежие фикстуры, а не рабочие аккаунты.
