# QAZAQMETAL 2.3.0+16 — участники и партнёры

## Кабинеты и отдельные приложения

- Участники: https://qazaqmetal.109.235.119.144.sslip.io — вход по табельному номеру.
- Партнёры: https://qazaqmetalpartners.109.235.119.144.sslip.io — вход по логину партнёра.
- Администрация: https://qazaqmetaladmin.109.235.119.144.sslip.io — вход по логину администратора.

Админский и партнёрский кабинеты используют широкую боковую панель на компьютере, а на телефоне — мобильные разделы и выдвижное меню. Проверки ширины: 320 и 390 px.

Приложение партнёра устанавливается рядом с приложением участника. Идентификаторы Android/iOS:

| Приложение | Идентификатор |
|---|---|
| Участник | `kz.qazaqmetal.qazaqmetal` |
| Партнёр | `kz.qazaqmetal.qazaqmetal.partner` |

Партнёрское приложение называется «QAZAQMETAL Партнёр», использует партнёрский HTTPS-адрес и отдельное защищённое хранилище сессии.

## PIN

Веб-кабинеты администрации и партнёров не создают и не запрашивают PIN. В мобильных приложениях участника и партнёра после авторизации настраивается шестизначный PIN. Пока сессия действует, повторный запуск запрашивает сохранённый PIN, а не логин и пароль. Обновление данных и системные диалоги PIN не вызывают. При возврате из фона действует пауза 30 секунд; холодный запуск всегда защищён PIN.

После выхода или новой авторизации старые PIN/биометрия удаляются; необходимо создать новый PIN. Обычная смена пароля в продолжающейся сессии сохраняет PIN. В пользовательской веб-версии обновление той же разблокированной вкладки не повторяет PIN: используется состояние вкладки, очищаемое при выходе. Новая вкладка имеет собственную блокировку.

## Заведение и скидка

Скидка, условия, начало и окончание периода находятся прямо в форме заведения. Отдельного раздела «Скидки и акции» нет. Создание заведения не требует отдельного создания предложения. Изменения названия, условий и процента публикуются одной заявкой после модерации; до одобрения участники видят прежние условия.

Ранее одобренные скидки демонстрационных заведений сохранены и подставляются при редактировании. Старые API-предложения поддерживаются для совместимости; после публикации скидки в заведении используется именно она. Недействующий период отключает привилегию, но не скрывает само заведение. QR не открывает произвольные ссылки и проверяет текущую доступность на сервере.

## Даты

Все поля дат выбираются календарём без ручного ввода. Отображение — **ДД.ММ.ГГГГ**. Внутренний API/CSV использует ISO; пользователь его не набирает. Начало не выбирается после окончания и наоборот. Дату можно очистить. Календарь и интерфейс локализованы на русский и казахский. Фильтры статистики также используют календарь.

## Уведомления

| Событие после модерации | Получатели |
|---|---|
| Первое опубликование нового заведения | Все действующие участники профсоюза, которым заведение доступно по организации; не партнёры и не администраторы |
| Новый баннер или новое изображение опубликованного баннера | Только участники, сохранившие заведение в избранное |
| Увеличение скидки | Только участники, сохранившие заведение в избранное |
| Уменьшение скидки | Уведомление не создаётся |
| Одобрение или отклонение изменений | Активные учётные записи владельца-партнёра; причина отклонения доступна в сообщении |

Запись в центре уведомлений и очередь доставки создаются в транзакции публикации. До модерации уведомлений участникам нет. Перед отправкой заново проверяются статус пользователя, доступность организации/заведения, принадлежность устройства и подписка на избранное, если она требуется. Новое заведение не требует избранного. Будущие предложения уведомляют с даты начала. При нажатии уведомления участник открывает заведение; опубликованные баннеры видны в его карточке. Партнёр видит результаты модерации в своём центре уведомлений.

## Подключение системной доставки позднее

Центр уведомлений работает через сервер без Firebase. В оба мобильных приложения включён SDK Firebase Messaging; без конфигурации проект не инициализируется и запрос разрешения не показывается. Реальная отправка сейчас не настроена и на физических устройствах не проверялась.

Для включения нужны четыре клиентские конфигурации Firebase (Android/iOS для двух идентификаторов выше), закрытый service-account для серверного FCM-отправителя, APNs-настройки и подпись Apple для iOS. Используйте один Firebase-проект для обоих приложений. Закрытый ключ хранится только на сервере и не входит в приложение/репозиторий.

Публичные клиентские параметры передаются переменной сервера `FIREBASE_CLIENT_CONFIG`, компактный JSON вида:

```json
{"member":{"android":{"apiKey":"CLIENT_KEY","appId":"MEMBER_ANDROID_APP_ID","messagingSenderId":"SENDER_ID","projectId":"PROJECT_ID"},"ios":{"apiKey":"CLIENT_KEY","appId":"MEMBER_IOS_APP_ID","messagingSenderId":"SENDER_ID","projectId":"PROJECT_ID","iosBundleId":"kz.qazaqmetal.qazaqmetal"}},"partner":{"android":{"apiKey":"CLIENT_KEY","appId":"PARTNER_ANDROID_APP_ID","messagingSenderId":"SENDER_ID","projectId":"PROJECT_ID"},"ios":{"apiKey":"CLIENT_KEY","appId":"PARTNER_IOS_APP_ID","messagingSenderId":"SENDER_ID","projectId":"PROJECT_ID","iosBundleId":"kz.qazaqmetal.qazaqmetal.partner"}}}
```

Это шаблон, не рабочие ключи. `/api/push-config` публикует только белый список клиентских идентификаторов и никогда не выдаёт закрытые поля. После конфигурации и включения серверного push-профиля приложения при следующем запуске запросят разрешение и зарегистрируют устройство. Для браузеров сейчас предусмотрен центр уведомлений; системный Web Push требует отдельной настройки VAPID/service worker.

## Повторная сборка

```bash
cd platform/client
flutter pub get --enforce-lockfile
flutter build web --release --no-web-resources-cdn --no-tree-shake-icons --output=../web
flutter build apk --debug --dart-define=API_BASE_URL=https://qazaqmetal.109.235.119.144.sslip.io
cd ..
python3 scripts/build_partner.py --platform android --mode debug
```

Member APK: `client/build/app/outputs/flutter-apk/app-debug.apk`.
Partner APK: `client/build/partner-app/QazaqMetal_Partner_debug.apk`.

На macOS с Xcode: `python3 scripts/build_partner.py --platform ios --mode release` создаёт независимый unsigned iOS-пакет. `--prepare-only` готовит отдельный проект для подписи в Xcode. Производственная Android-подпись требует своего `key.properties` с абсолютным путём к keystore (`--android-signing-file /private/key.properties`). Закрытые файлы не копируются автоматически. Для iOS заданы Push Notifications и APNs development/production по конфигурации сборки. Публикация в магазинах требует учётных записей и подписей владельца; debug APK не является production-релизом.

## Проверки

PostgreSQL: единое заведение/скидка, отложенная публикация, QR, периоды, уведомления избранного, аудитории новых заведений и защита конфигурации. Flutter: PIN для ролей, возврат из фона, отсутствие повторного PIN при диалогах, календарь, формат даты, мобильные кабинеты и навигация. Браузерные проверки опубликованной версии и точные итоговые количества будут приложены к релизу. Физические телефоны и доставка через реальные Firebase/APNs проверяются после получения конфигурации и устройств.
