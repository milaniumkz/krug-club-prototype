# Воспроизводимое нагрузочное тестирование

Запускать только на отдельной пустой базе `qazaqmetal_load` и собственном loopback-сервере. Скрипт отказывается обращаться к публичным адресам. Карты OpenStreetMap и сторонние сервисы в нагрузку не входят.

1. Создайте отдельную PostgreSQL-базу `qazaqmetal_load`. Задайте её URL через `DATABASE_URL` в окружении, без записи пароля в репозиторий. Не используйте рабочую базу.
2. Из `platform/server`: `pip install -r requirements-load.txt`, затем `alembic upgrade head`.
3. Из `platform`: `python scripts/seed_load.py --private-output /tmp/qm-private-fixture`. Скрипт требует пустую базу и создаёт 10 000 синтетических участников, 100 заведений, 200 предложений, 20 000 операций истории. Файл `accounts.json` содержит тестовые секреты: храните его приватно. Общий тестовый пароль создан исключительно для нагрузочных данных; рабочий импорт выдаёт индивидуальные пароли.
4. Из `server`: `uvicorn app.main:app --host 127.0.0.1 --port 8091 --workers 2 --no-access-log --timeout-keep-alive 60`. Используйте `ulimit -n 16384`. Для реальной эксплуатации используйте HTTPS и инструкции основного README.
5. Из `platform`:

```bash
python scripts/load_test.py --url http://127.0.0.1:8091 \
  --fixture /tmp/qm-private-fixture/accounts.json --mode burst \
  --workload mixed --count 5000 --preconnect --timeout 45 \
  --label mixed-5000 --output artifacts/load/mixed-5000

python scripts/load_test.py --url http://127.0.0.1:8091 \
  --fixture /tmp/qm-private-fixture/accounts.json --mode steady \
  --workload mixed --rate 5000 --duration 10 --concurrency 5000 --timeout 45 \
  --label steady-5000 --output artifacts/load/steady-5000
```

Повторите `burst` без `--preconnect` для холодных соединений. Для HTTPS задайте URL `https://localhost:8443` и `--ca /private/path/root.crt`; проверка сертификата не отключается. Имя TLS должно соответствовать сертификату. Прокси не должен перехватывать соединение между Caddy и API (`NO_PROXY=api,db,localhost,127.0.0.1,::1`).

Доступные нагрузки: `health`, `meta`, `me`, `catalog`, `detail`, `map`, `history`, `stats`, `scan`, `login`, `mixed`. В `mixed`: каталог 40%, карточка 20%, карта 15%, история 15%, профиль 10%. Чтения используют разные сессии участников; QR и вход проверяются отдельно. Картинки и тайлы не скачиваются этим генератором.

`preconnect` открывает соединения до старта таймера; время подготовки вынесено отдельно. `peak_outstanding` означает незавершённые клиентские запросы, а не число параллельно работающих потоков базы. `headers_dispatch_span_ms` — интервал отправки, **не время обработки**. Смотрите `batch_completion_ms`, квантили, HTTP-статусы и транспортные ошибки.

В режиме `steady` очередь ограничена `--concurrency`. `not_dispatched` — запланированные запросы, которые генератор **не отправил** из-за заполнения очереди; это не успешные запросы и не ответы сервера. Их нужно включать в оценку невыполненной нагрузки. `success_rps_within_offering_window` отличается от частоты с учётом ожидания завершения хвоста.

Подготовленные сессии не заменяют нагрузку проверки паролей. `login` использует настоящую проверку Argon2. Не снижайте стойкость хеширования ради красивой цифры. Повторный QR одного участника в течение 60 секунд возвращает ранее сохранённую операцию; при повторных замерах считайте именно прирост истории, а не число HTTP 200.

API ограничивает работу с БД десятью запросами на worker, ожидание допуска — 30 секунд. При перегрузке возвращается 503 и `Retry-After: 2`; клиент должен повторять с паузой. Два worker и эти настройки не являются гарантией 5 000 RPS. Целевую пропускную способность следует подтвердить на будущем сервере с отдельного генератора нагрузки, HTTPS, реалистичной базой, изображениями и измерением CPU/RAM/диска.

Функциональные проверки: `cd server && pytest -q` (для конкуренции задайте отдельную `TEST_DATABASE_URL`, содержащую `qazaqmetal_test`); `cd client && flutter analyze && flutter test`. Браузерные сценарии — `scripts/browser_smoke.py`, `browser_navigation.py`, `browser_interactions.py`, с приватным QA-файлом учётных данных и собственным тестовым URL. Они не проверяют физическую камеру, Android Back и iOS-жесты на телефоне.
